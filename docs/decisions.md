## 決定事項

### 開発環境と安全対策（2026-11-11）

| 決定 | 理由 |
| --- | --- |
| Node と Python はホストに入れず、digest で固定したイメージのコンテナで動かす | ローカル環境を汚さず、依存のコードがホストのファイルや権限に触れないようにするため |
| 依存は `vite` 8.3.5、`typescript` 7.0.2、`vitest` 5.1.0 に固定。lock の全 81 パッケージが公開 7 日以上・sha512 付き・公式レジストリ由来であることを確認した | 公開直後の版に混入した悪意あるコードを避けるため |
| テスト・バランス検証・型検査・ビルドはネットワークなしのコンテナで動かす | 依存のコードが外部と通信できないようにするため |
| `npm run sim` は実行用の道具を足さず、Node の型の取り除きで TypeScript をそのまま実行する | 開発用の依存を Vite・TypeScript・Vitest の 3 つに保つため。代わりに import の拡張子を `.ts` まで書く |
| 型定義の依存（`@types/node`）を入れない | 同上。Node の値を使うのは 2 か所だけなので、その場で宣言すれば足りる |
| CI（GitHub Actions）は型検査・テスト・バランス検証・ビルドだけを行い、公開はしない | 公開先が未定のため。Action はコミット SHA で固定し、権限は読み取りだけにした |
| `index.html` に CSP を入れ、外部の読み込み・通信とインラインの script・style を禁じる | 実行時に外部へ頼るものがないので、禁じても困らず、万一の混入の被害を小さくできる |
| 見た目の確認には、手元にあった Playwright 公式イメージの Chromium を使う。確認用スクリプトはリポジトリに入れない | 依存を増やさずに実際の描画を確かめるため |
| 参照シミュレータは、使う CPU を 4 個に絞って動かす（2026-11-12） | 並列数を絞らないと、並列のワーカーが Segmentation fault で落ち、結果を待ったまま止まることが繰り返し起きたため。Python 3.12 と 3.13 のどちらでも起き、原因は特定していない。4 個に絞ると 10 回続けて数秒で「総合: 合格」になった。参照シミュレータのコードは変えていない |

| 決定 | 理由 |

### 位置取りで狙う形への作り替え（2026-11-12）

依頼者が遊んだ感想（「左右どちらを選ぶかしかなく、ゲームとして成立しているか分からない」）を受けて、操作とルールを作り替えた。作り替えは `aim-redesign` ブランチで行い、以前の版は `main` に残してある。

| 決定 | 理由 |
| --- | --- |
| 2 つのレーンを切り替える操作をやめ、左右に動いて正面を撃つ操作にした | 以前の版は、判断が「数字が白いか」「ゲージが高いか」で決まり、選んだあとは見ているだけだった。自動プレイヤーで測っても、ふつうの人とほぼ最善手の生存時間の差が 1.22 倍しかなかった。作り替えたあとは 1.47 倍 |
| 自由に狙う形（指した場所へ撃つ）ではなく、位置取りで狙う形にした | このジャンルの広告ゲームの元の操作で、指 1 本・片手で遊べる。「敵か強化か」の板挟みと題名をそのまま生かせる |
| 敵を道の中央、強化ブロックを左右の端に置いた | 最初は敵を左、強化 2 列を右に並べたが、奥の列へ行く途中で手前の列を必ず横切り、避けたい罠を撃ってしまった（上手いボットでも 1 プレイに罠を 11〜14 個壊した）。中央を敵にすると、横切るときに撃つのは敵だけになり、移動が無駄にならない |
| 強化ブロックを 2 個 1 組にし、両方壊すと「両取り」にした | 「どちらを取るか」「両方取れるか」という選択を作るため。以前は 1 個ずつ決まった順に来るので、取るか見送るかしかなかった |
| 敵の数を減らし、1 体を硬くした（未読通知をサイズ 2.5・HP 2.5 倍に） | 1 体が 0.1 秒で倒れるままだと、狙う間もなく左右に振るだけになる。持ち込まれる HP とサイズの合計（バランスの土台）は変えていない |
| 敵の種類ごとに幅を持たせ、幅の広い敵が後ろの敵の盾になるようにした | 「割の悪い締切は後回しにしたいのに邪魔になる」「かたまった迷惑メールはまとめて倒せる」という、狙う相手を選ぶ理由を作るため |
| 段の相方は、罠と帽子を多め（山 40 枚中 21 枚）にした | ボムと有給休暇を多くすると、上手いボットが 8 分近く生き残り、強化だけを追うボットが 11 分生き残る回も出た。相方が外れの段は「ランクアップだけ取って戻る」段になる。ここは遊んだ感触で見直す余地がある |
| 圧力比を「初期値 0.26、伸び率 0.004」に変えた（以前は 0.30、0.0034） | 狙いを合わせる移動のぶん序盤が忙しくなるので初期値を下げ、上手い人が長く生き残りすぎないよう伸び率を上げた |
| 参照シミュレータ（Python）も新しいルールに書き直した | TypeScript とは別に書いた実装の結果が一致することで、仕様の読み違いがないことを確かめるため。全ボット・種 0〜9 で小数第 2 位まで一致した |
| 弾の列を、足元から当たっている標的まで薄く光らせ、削れた敵には残り HP のバーを出す | 狙いがどこに当たっているか、どの敵が倒れかけかが見えないと、位置取りの判断ができない |
| 「惜しい！」と、リザルトの「惜しい取り逃し」は、罠と帽子以外を半分以上削った場合だけにした | 通りがかりに少し当たっただけのブロックや、取らなくてよい帽子で「惜しい」と出ると、意味が薄れる |

確かめられていないこと: 自動プレイヤーは狙いを外さないので、動く速さ（毎秒 3）と弾の当たる幅（0.06）が人にとって気持ちよいかは測れていない。仕様書 3.6 節のつまみで変えても、自動プレイヤーの生存時間はほとんど動かなかった。ここは依頼者が遊んだ感触で決める。

### バランスの確認（2026-11-12）

依頼者の「ゲームバランスも問題ないか確認を」を受けて、中央値のほかに負け方・序盤の忙しさ・罠の重さ・狙い方の効き目を測った。数値は仕様書 11.2 節。

| 分かったこと | 判断 |
| --- | --- |
| 生存時間の中央値は、デモ 79 秒、慎重 158 秒、ふつう 258 秒、上手い 339 秒、ほぼ最善 378 秒。最長は 520 秒 | 狙いどおり。合格範囲に収まっている |
| 序盤 1 分で、時間の 6 割を強化の帯で過ごす。負ける前に 13〜18 秒のじわじわ埋まる時間がある。罠の直後に負ける回はほぼない | 問題なし |
| ボットが、危ないときにボムを取りに行かなかった（埋まり度が上がると強化をあきらめる作りだった） | 測る道具の側の不備。埋まり度 50% 超のボムは最優先で取りに行くよう直した（TypeScript と Python の両方。結果は一致のまま）。慎重が 143 → 158 秒、ふつうが 245 → 258 秒に伸びた |
| 埋まり度が 70% を超えると、そのまま負けることが多い。80% を超えるとほぼ負ける | 弱点。逆転の場面が少ない。「持ち直した！」の条件を、危険の警告と同じ 70% からに合わせた（80% のままだと、ほぼ出ない）。根本的に直すにはルールの変更が要る（下の提案） |
| 敵の狙い方は、生存時間にほとんど効かない（効率で狙っても古い順でも同じ。左右に振るだけでも同じ） | 弱点。「狙う手応え」は見た目と操作の忙しさとしては出ているが、うまく狙うほど得をする仕組みにはなっていない。直すにはルールの変更が要る（下の提案） |
| 立ち位置に ±0.15 のぶれを入れても、弾の列の幅を変えても、生存時間は変わらない | 人が多少狙いを外しても不利にならない、という意味では安心材料。裏を返せば、上の弱点と同じこと |

## 提案

スコアや生存時間に効く案は、ここに書いて依頼者の判断を待ちます（`CLAUDE.md` の「改善の進め方」）。上にあるものほど、おすすめです。

### 遊びを面白くする案

- **今日の挑戦（おすすめ）**: 日付から決まる同じ種で、誰が遊んでも同じブロックと敵が流れてくる遊び方をタイトルに足す。「結果をコピー」に日付が入り、人と比べる意味が生まれる。ルールにもバランスにも影響しない。タイトル画面にボタンが 1 つ増え、ハイスコアを通常と分けて持つ（保存するキーが 1 つ増える）。
- **狙うほど得をする仕組み（おすすめ）**: いまは、どの敵を撃っても同じ結果になる。たとえば、リボ払いの育つ速さを上げる（放っておくと損が大きい）、迷惑メールのかたまりを正面に捉えたときだけ貫通の威力を上げる、締切の後ろの敵にも一部ダメージが通る「弱点」を作る、など。どれも生存時間に効くので、数値の再調整と参照シミュレータの作り直しが要る。
- **逆転の余地**: 埋まり度が高いほどボムの消せる量が増える、ラッシュの前に必ずボムか有給休暇が来るようにする、など。70% を超えてからの持ち直しを増やす。生存時間に効く。
- **段の相方の見直し**: いまは相方の半分が罠か帽子で、「ランクアップだけ取って戻る」段が多い。ボムや有給休暇を増やすと上手い人が生き残りすぎたので、増やすなら効き目を弱める（ボムで消せる量を減らす、有給休暇を短くする）か、新しい種類のブロックを足す。生存時間に効く。
- **ギリギリのボーナス**: 通過まで 0.6 秒を切ってブロックを壊すと、スコアが 2 倍入る。欲張る理由が増える。スコアだけに影響し、生存時間は変わらない。
- **ボスの個性**: いまは 4 体とも性能が同じ。たとえば「スキップできない広告」は出現から 5 秒間ダメージが通らない、「確定申告」は倒すまで迷惑メールを出し続ける、など。ボスごとに作戦が変わるが、生存時間に効くので、数値の再調整と参照シミュレータの作り直しが要る。
- **取り逃しの救済**: 残り 15% 未満で通過しそうなブロックは、通過線の上で 0.5 秒だけ粘る。「惜しい！」の悔しさは減るが、判断が甘くなるので慎重に。生存時間に効く。

### そのほか

- **公開用のワークフロー**: 公開先が GitHub Pages に決まったら、CI が通ったあとに `dist/` を公開するジョブを足せます。書き込み権限は公開のジョブだけに付けます。
- **音の初期設定**: いまは初めからオンです。初めはオフにして、遊ぶ人が入れる形にもできます。
- **画面を横に回したときの案内**: 縦持ち固定の想定ですが、横向きでも縮小して表示されるだけで、案内は出していません。必要なら「縦にしてください」を出せます。
- **操作の案内の出し分け**: 仕様どおり「タップで移動」と出しています。PC では「← → キーで移動」に変えることもできます。
