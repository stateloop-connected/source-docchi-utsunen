# これを読んで進めてください

ブラウザゲーム「どっち撃つねん」の実装を依頼します。企画と仕様は固まっていて、バランスの数値は参照シミュレータで検証済みです。あなたの仕事は、仕様書どおりに実装し、段階ごとに完了条件を確かめることです。

## このリポジトリに入っているもの

| ファイル | 中身 | 読み方 |
| --- | --- | --- |
| `CLAUDE.md` | 常に守る決まり | 最初に読む |
| `docs/spec.md` | 仕様書（実装の正） | 全文を読む。特に 2〜4 章と 8〜10 章 |
| `docs/proposal.md` | 企画書（背景と狙い） | 一度通読する。見た目・文言で迷ったときに戻る |
| `reference/balance_sim.py` | 仕様を実装した Python の参照シミュレータ | 手順に迷ったら読む。`step` の処理順は仕様書 2.7 節と 1 対 1 で対応している |
| `reference/golden.json` | 単体テスト用の期待値 | 段階 1 のテストで使う |

## 最初にやること

1. `CLAUDE.md`、この文書、`docs/spec.md` を読む。
2. `docker compose run --rm reference` で参照シミュレータを実行し、「総合: 合格」と出すことを確かめる（数分〜十数分）。
3. 読んで不明な点・矛盾に見える点があれば、実装を始める前にまとめて依頼者に質問する。なければ段階 1 に進む。

## 進め方

仕様書 10 章の 6 段階を順に進めます。各段階の終わりに、完了条件を満たした証拠（テストやコマンドの出力）を添えて依頼者に報告し、コミットしてから次へ進んでください。

| 段階 | 作るもの | 完了条件 | 仕様書の該当箇所 |
| --- | --- | --- | --- |
| 1. ルールの芯 | Vite + TypeScript + Vitest の土台、`src/core/` 一式、単体テスト | `golden.json` と一致（乱数と袋は完全一致、数式は相対誤差 1e-9 以内）。同じ種と入力で結果が一致 | 2、3、4、8 章 |
| 2. バランス検証 | `src/bots/`、`src/sim/cli.ts`、`npm run sim` | 9.2 節の合格基準をすべて満たす | 5.1 節、9 章 |
| 3. 遊べる最小版 | 遠近法の描画、入力、表示類、ゲームオーバーとやり直し | スマホと PC で 1 プレイ通して遊べる | 6 章 |
| 4. デモとタイトル | デモ AI の組み込み、広告風の飾り | デモが負けては繰り返す。「今すぐプレイ」で本編が始まる | 5 章 |
| 5. 演出と音 | 演出、音、リザルト、ハイスコア保存、一時停止 | 7 章の表の全行が実装されている | 7 章 |

**段階 2 を通るまで、描画には着手しないでください。** バランスの芯が仕様どおりに動くことを先に確かめるためです。

## 段階 1 のテストに含めるもの

- `mulberry32` が `golden.json` の `mulberry32` と完全に一致する（種 0 と 12345 の最初の 5 個）
- 数式（φ、基準火力、サイズ流入、基礎 HP、WAVE 番号）が `golden.json` の `formulas` と一致する
- ボスの HP が `golden.json` の `boss` と、ランクごとの DPS が `dps` と一致する
- ブロックの順番が `golden.json` の `deck` と完全に一致する（種 0、1、2、42 の最初の 61 個）
- 同じ種・同じ入力列で `step` を回すと、状態が完全に一致する
- 入力なし（常に敵レーン）で、ランクが 0 のまま、およそ 95 秒で終わる
- 仕様書 4.2 節の各ブロックの効果（ボムの消し方、有給休暇の延長、増築の上限、罠の出現数）

## 段階 2 で数値が合わないとき

仕様書 9.3 節の順に確認します。特に間違えやすい箇所は次のとおりです。

- 経過時間を足し込んでいる（刻み数 ÷ 60 で求める）
- 1 刻みの処理順が 2.7 節と違う（敵の出現 → ブロックの出現 → 通過 → 相棒 → プレイヤーの順）
- 迷惑メールの s̄・m̄ を 1 通分で計算している（8 通分で計算する）
- ボス戦のウェーブで、ラッシュ中に通常の敵を出している
- ブロックの HP に相棒の火力を含めている、または出現後に HP を変えている
- ボットの「前回の希望」を「今いるレーン」と取り違えている
- 乱数列を 1 本で済ませている（ブロック用・敵用・ボット用を分ける）

`golden.json` の `sim_reference.first10_seeds` に、参照シミュレータでの種 0〜9 の生存時間があります。完全一致は必須ではありませんが、大きくずれている種があれば、その種を参照シミュレータと並べて追うと原因が見つかります。

## 判断に迷ったとき

| 迷いの種類 | どうするか |
| --- | --- |
| バランスに関わる（数値、手順、スコア、ボットの挙動） | 自分で決めずに依頼者に確認する |
| 仕様書と参照コードの食い違い | 依頼者に確認する |
| 見た目、音、文言、画面の細かい配置 | 自分で決めて進め、決めたことを README に残す |
| 仕様にない機能を足したくなった | 足さずに、提案として報告する |

## まだ決まっていないこと

実装は止めずに進めてください。関係する箇所は、あとで差し替えやすいように作ります。

- 敵のネタ（名前と見た目）が変わる可能性がある → 名前と絵は `balance.ts` と `sprites` に閉じ込める
- 公開先が未定 → Vite の `base` は `'./'` にしておく
- 1 プレイの長さを変える可能性がある → 調整つまみ（仕様書 3.6 節）だけで変えられるようにしておく
