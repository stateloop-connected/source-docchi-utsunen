# 実装の今の姿

コードの構成、仕様書が実装者に任せた部分の決定、確認のしかたを書きます。ルールと数値は `docs/spec.md` が正で、ここには写しません。コードを変えたら、同じ変更の中でこの文書の該当する節を書き換えます。

## 構成

| パス | 中身 |
| --- | --- |
| `index.html` | 入口。CSP の meta、キャンバス 1 枚 |
| `src/core/balance.ts` | 仕様書 3 章・4 章の全数値と表、敵・ブロック・武器・ボスの名前 |
| `src/core/formulas.ts` | 数式（DPS、基準火力、圧力比、サイズ流入、基礎 HP）と、武器名・ボス名・発射数・推定 IQ |
| `src/core/rng.ts` | 種つき乱数（mulberry32）とシャッフル。内部状態は数値 1 つ |
| `src/core/deck.ts` | ブロックの袋と山 |
| `src/core/state.ts` | ゲーム状態と出来事の型、`createGame(seed)` |

| `src/render/projection.ts` | 遠近法の式とレーンの範囲 |
| `src/render/sprites.ts` | 全スプライトの絵と色。ID から引く（`sprite(id)`、`drawSprite`） |
| `src/render/view.ts` | 見た目だけの状態（敵の位置、弾、数字、破片、演出のタイマー）と、出来事への反応 |
| `src/render/scene.ts` | 背景、道、敵、ブロック、プレイヤー、弾、エフェクトの描画 |
| `src/render/hud.ts` | 埋まり度ゲージ、WAVE、スコア、武器名、警告、案内、中央に出る文字 |
| `src/render/format.ts` | 数字の表示（K・M・B・T、3 桁区切り） |
| `src/render/draw.ts` | キャンバス描画の小さな道具とフォント指定 |
| `src/audio/synth.ts` | 効果音、BGM、心拍の合成 |
| `src/app/main.ts` | 起動、画面遷移、入力、毎フレームの更新と描画 |
| `src/app/session.ts` | 1 回分のゲーム（状態 + 見た目 + デモなら AI）。経過時間を貯めて step を回す |
| `src/app/screens.ts` | タイトル・一時停止・リザルトの重ね描き、ボタン配置、煽り文句、コピーする文字列 |
| `src/app/ui.ts` | キャンバス上のボタン（当たり判定と描画） |
| `src/app/storage.ts` | localStorage（ハイスコアと音の設定） |
| `tests/` | 単体テスト。`reference/golden.json` を直接読んで比べる |
| `compose.yaml` | 開発・テスト・検証・ビルドを Docker で動かす設定 |
| `.github/workflows/ci.yml` | push と pull request で型検査・テスト・バランス検証・ビルドを行う |

依存の向きは `app` → `render`・`audio`・`bots` → `core` の一方向です。`core` はほかのどこも読みません。

## core の作り

- 状態は関数を持たないただのデータで、`JSON.stringify` でそのまま比べられる。再現性のテストはこれを使っている。
- 敵の列は配列と先頭位置（`head`）で持ち、倒した敵は先頭位置を進めるだけにする。抜け殻が 256 を超えて列の半分以上になったら詰め直す。一斉削除のときだけ配列を作り直す。
- 埋まり度は合計を数え直さず、敵の増減のたびに足し引きする。
- 乱数は、ブロック用（`state.deck.rng`）と敵の出現用（`state.spawnRng`）を状態に持つ。ボット用は `src/bots/bot.ts` が、見た目用は `View` が持つ。
- 数式の計算の順序は参照シミュレータに合わせてある。種 0〜9 の生存時間が全ボットで参照と小数第 2 位まで一致する。

## 画面の作り

- 本編もデモも `Session` が同じ `step` を回す。違いは、希望レーンを人の入力から取るか、デモ AI から取るかと、効果音の出口を渡すかどうかだけ。
- `View` は core の状態を読むだけで書き換えない。敵の見た目（横位置、奥行き、絵の変種）は、敵の通し番号をキーにした表で持つ。
- 敵は列の後ろほど奥にいるので、列を後ろから描けば奥から手前の順になる（並べ替えをしない）。
- 背景（空、街並み、道）と赤い縁取りは、起動時に 1 枚の絵にしておく。
- 演出と音は、`step` が返した出来事を `View.handle` が受けて出す。射撃と命中は出来事ではなく、`View.update` が発射数から弾と数字を作る。
- レーザーと波動砲は弾ではなく、プレイヤーから標的までの光の帯として描く。ねこは弾も帯も出さず、標的の位置に数字ときらめきだけを出す。
- 開発サーバーで動かしているときだけ、`window.app` からアプリの状態に触れる（本番ビルドには含まれない）。

## 実装で決めたこと

仕様書が実装者に任せた、見た目・音・文言の決定です。

### 見た目

- 背景は青空、遠くの街並み、緑の地面。道は灰色で、敵レーンに薄い赤、強化レーンに薄い青を重ねて区別する。今いるレーンの足元を白く光らせる。
- プレイヤーは奥を向いた後ろ姿で、武器は体の右に構える（頭に帽子を積むため）。相棒は防衛線の上に左・右・中央の順で並び、敵の先頭へ緑の線を出す。
- 未読通知のバッジの数字は 6 通りを使い回す。5 体目以降のボス（「真・」）は紫の光をまとう。
- 敵は少し上下に揺れる。ブロックは、撃たれている間と残り 15% 未満のときに震える。
- ブロックを壊したときに中央へ出す効果名は、ランクアップ！、ランク +2！！、相棒 参上！、一斉削除！、有給休暇！、増築！、罠だ！！、帽子ゲット…。ボスを倒すと「〈ボス名〉撃破！」。
- 有給休暇の効果中は、敵レーンを水色にして残り秒数を道の上に出す。
- ボスが出た瞬間は、画面中央の帯に名前を大きく 1.6 秒出す。ボスがいる間は、中央上に名前と HP バーを出す。
- WAVE の進行バーは、凪を青、ラッシュを赤、ボス戦のウェーブのラッシュを紫で塗る。
- ゲームオーバーでは、敵のスプライトが手前へ大きくなりながらなだれ込み、画面が赤黒くなる。
- リザルトの推定 IQ が 62 以下なら赤字にして「（広告の人と同じ）」を添える（62 はデモのスコアの中央値にあたる）。
- 「結果をコピー」は、成功すると「コピーしました」、クリップボードが使えない環境では文字列そのものを画面に出す。

### 仕様書の表示との違い

- プレイ中のスコアは、K・M 表記ではなく 3 桁区切りの整数で出す。1 点単位で増えるのが見えたほうが気持ちよいため。HP、DPS、ダメージは仕様どおり K・M・B・T。
- タイトル画面では、右上の「✕」のために埋まり度ゲージの幅を 460 にし、下端の「今すぐプレイ」のために武器名と DPS をスコアの下へ移している。警告の文字も小さくしている。
- 開始 10 秒間の案内は、手前の敵と重ならないよう道の中ほど（y 470〜554）に出す。

### 音

- 音は初めはオン。最初のタップかキー入力で鳴り始める。設定は `docchi-utsunen.sound` に `on` / `off` で保存する。
- 発射音は武器の段階ごとに、波形・高さ・長さ・ノイズの量を変えている（`src/audio/synth.ts` の `SHOTS`）。
- BGM はノコギリ波のベースとノイズのハイハット。テンポは WAVE 1 で 104、1 ウェーブごとに +4、上限 168。ラッシュ中はハイハットを倍に刻む。
- 心拍は埋まり度 70% で 0.95 秒間隔、100% で 0.38 秒間隔。
- タイトル画面のボタンを押したときだけ、デモ中でも小さな操作音が鳴る（デモ自体の音は鳴らさない）。

### 操作

- タップとクリックは画面全体で受ける。キャンバスの外の黒い余白を押してもレーンが切り替わる。
- タイトル・一時停止・リザルトでは、Tab か矢印キーでボタンを選び、Enter かスペースで決定する。何も選んでいないときの決定は、いちばん上のボタン（今すぐプレイ、再開、もう一度）に効く。
- 実解像度は devicePixelRatio に合わせるが、2 倍を上限にしている。

## 確認のしかた

- 単体テスト・バランス検証・型検査・ビルドのコマンドは `CLAUDE.md` の「コマンド」。
- 参照との一致を種ごとに見るときは `docker compose run --rm sim node src/sim/cli.ts --seeds` の出力を、`reference/golden.json` の `sim_reference.*.first10_seeds` と見比べる。
- 見た目は、Playwright 公式イメージ（digest 固定）の Chromium を CDP で操作してスクリーンショットを撮る。npm パッケージは入れず、Node 標準の `fetch` と `WebSocket` を使う。確認用スクリプトと撮った画像はリポジトリに入れない。
    - コンテナは compose のネットワーク（`docchi-utsunen_default`）につなぎ、開発サーバーのコンテナの IP アドレスで開く（Vite は知らないホスト名での接続を拒むため。IP は `docker inspect` で調べる）。
    - 和文は Windows のフォントフォルダを読み取り専用でマウントして `fc-cache -f` する。Chromium には `--no-sandbox`（権限を落としたコンテナではサンドボックスを作れない）と `--disable-dev-shm-usage` を付ける。
    - 後半の場面を作るには、`window.app` から `app.session.advance(1/60)` を繰り返し呼んで早送りし、`app.session.state` を書き換える。ボットに遊ばせるなら、ページ内で `import('/src/bots/threshold.ts')` する。
    - スマホ向けの確認は、タッチのエミュレーション（390 × 800 など）で行う。キャンバスが画面より小さいと上下に余白ができるので、タップする座標は余白のぶんずらす。
    - 本番ビルドは `preview` を同じ方法で開く。CSP 違反はコンソールのログに出るので、ログが空であることを確かめる。
- 混雑時の重さは、敵を 285 体置いて更新と描画を 120 回まわし、1 回あたりの時間を測った（ヘッドレスの Chromium で約 3.8 ミリ秒）。
